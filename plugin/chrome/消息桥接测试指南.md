# 消息桥接测试指南

## 问题解决方案

### 问题描述
Login.vue 使用 `window.postMessage()` 发送登录消息，但 background.js 的 `chrome.runtime.onMessageExternal` 无法接收。

### 根本原因
- `window.postMessage()` 用于窗口/iframe 通信（DOM 层面）
- `chrome.runtime.onMessageExternal` 用于接收外部网站通过 `chrome.runtime.sendMessage(extensionId)` 发送的消息（扩展 API 层面）
- **这是两个完全不同的 API**

### 解决方案
创建消息桥接脚本 (`messageBridge.js`)，作为中间层：

```
Login.vue (Web 页面)
    ↓ window.postMessage()
messageBridge.js (Content Script)
    ↓ chrome.runtime.sendMessage()
background.js (Service Worker)
```

## 实现细节

### 1. messageBridge.js
**位置**: `chrome/js2/messageBridge.js`

**功能**:
- 监听来自网页的 `window.postMessage()` 消息
- 检查消息来源是否为 `YINIAN_WEB`
- 将消息转发给 background.js

**关键代码**:
```javascript
window.addEventListener('message', (event) => {
    if (event.source !== window) return;

    const message = event.data;
    if (message.source !== 'YINIAN_WEB') return;

    if (message.type === 'PLUGIN_LOGIN_SUCCESS') {
        chrome.runtime.sendMessage({
            type: 'login',
            data: { token: message.auth }
        }, callback);
    }
});
```

### 2. background.js 修改
**位置**: `chrome/js2/background.js` (100-109行)

**修改内容**: 在 `onMessage` 监听器的 messageHandlers 中添加：
```javascript
login: () => {
    console.log("📨 [Background] 收到来自桥接脚本的登录消息");
    AuthModule.handleExternalLogin(message, sendResponse)
        .catch((error) => sendResponse({ error: error.message }));
},
logout: () => {
    console.log("📨 [Background] 收到来自桥接脚本的登出消息");
    AuthModule.handleExternalLogout(sendResponse)
        .catch((error) => sendResponse({ error: error.message }));
}
```

### 3. manifest.json 修改
**位置**: `chrome/manifest.json` (51行)

**修改内容**: 在 content_scripts 中添加 messageBridge.js：
```json
"js": [
    "js2/messageBridge.js",     // ✅ 新增
    "js2/configContent.js",
    "js2/content.js",
    "js2/resumeInterfaceTwo.js"
]
```

## 故障排查

### 问题 1: 网页控制台没有看到"消息桥接脚本已加载"
**原因**: messageBridge.js 未注入
**解决**:
1. 检查 manifest.json 是否正确添加了 messageBridge.js
2. 重新加载扩展 (chrome://extensions/ -> 点击刷新按钮)
3. 刷新登录页面

### 问题 2: 网页控制台看到"消息桥接脚本已加载"，但没有收到消息
**原因**: Login.vue 的 postMessage 未触发，或消息格式不对
**检查**:
1. Login.vue 的 284-288 行代码是否正确执行
2. postMessage 的 source 字段是否为 'YINIAN_WEB'
3. postMessage 的 type 字段是否为 'PLUGIN_LOGIN_SUCCESS'

**调试代码**（在 Login.vue 284行前添加）:
```javascript
console.log("📤 [Login.vue] 准备发送 postMessage:", authData);
window.postMessage({
    source: 'YINIAN_WEB',
    type: 'PLUGIN_LOGIN_SUCCESS',
    auth: authData
}, '*');
console.log("✅ [Login.vue] postMessage 已发送");
```

### 问题 3: 网页控制台收到消息，但 Service Worker 没有日志
**原因**: chrome.runtime.sendMessage() 失败
**检查**:
1. 网页控制台是否有错误日志
2. 检查 messageBridge.js 中的 chrome.runtime.lastError

**调试**: 在 messageBridge.js 的第 48 行添加:
```javascript
if (chrome.runtime.lastError) {
    console.error("❌ [消息桥接] 详细错误:", chrome.runtime.lastError);
    console.error("❌ 可能原因: background.js 未正确加载或消息处理器未注册");
}
```

### 问题 4: Service Worker 收到消息，但 AuthModule 处理失败
**原因**: AuthModule.handleExternalLogin 执行错误
**检查**:
1. Service Worker 控制台的完整错误堆栈
2. AuthModule 的实现是否正确
3. message.data.token 的格式是否符合预期

## 消息格式说明

### Login.vue 发送格式
```javascript
window.postMessage({
    source: 'YINIAN_WEB',              // 必须
    type: 'PLUGIN_LOGIN_SUCCESS',      // 必须
    auth: {                             // 必须
        accessToken: 'xxx',
        refreshToken: 'xxx',
        userInfo: { ... }
    }
}, '*');
```

### messageBridge.js 转发格式
```javascript
chrome.runtime.sendMessage({
    type: 'login',                     // 必须
    data: {                            // 必须
        token: {
            accessToken: 'xxx',
            refreshToken: 'xxx',
            userInfo: { ... }
        }
    }
});
```

### background.js 接收格式
```javascript
// message.type === 'login'
// message.data.token === { accessToken, refreshToken, userInfo }
```

## 与 externally_connectable 的区别

### externally_connectable 方式
```javascript
// 网页直接调用（需要知道扩展ID）
chrome.runtime.sendMessage('extension-id', { ... });
```

**优点**: 直接、简单
**缺点**: 需要硬编码扩展ID，开发/生产环境 ID 不同

### messageBridge 方式（当前实现）
```javascript
// 网页使用标准 Web API
window.postMessage({ ... }, '*');
```

**优点**:
- 网页不需要知道扩展ID
- 扩展未安装时不会报错
- 更符合 Web 标准

**缺点**: 多了一层转发

## 后续优化建议

### 1. 添加双向通信
messageBridge.js 已实现从扩展到网页的响应：
```javascript
window.postMessage({
    source: 'YINIAN_EXTENSION',
    type: 'PLUGIN_LOGIN_RESPONSE',
    success: true,
    response: response
}, '*');
```

Login.vue 可以监听此消息：
```javascript
window.addEventListener('message', (event) => {
    if (event.data.source === 'YINIAN_EXTENSION') {
        console.log('扩展响应:', event.data);
    }
});
```

### 2. 添加消息签名/验证
防止恶意网站伪造消息：
```javascript
// 可以使用共享密钥或时间戳验证
if (!isValidMessage(message)) {
    console.warn('非法消息，已拒绝');
    return;
}
```

### 3. 限制消息来源
在 messageBridge.js 中检查来源 URL：
```javascript
const allowedOrigins = [
    'http://192.168.1.144',
    'http://localhost',
    'https://applymind.cn'
];

if (!allowedOrigins.some(origin => window.location.origin.includes(origin))) {
    return; // 拒绝非授权域名的消息
}
```
